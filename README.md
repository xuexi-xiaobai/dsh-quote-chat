# dsh-quote-chat · 划词注释

在模型回答里划选一段文字（或指向一张表格），得到两个动作：

- **添加注释** —— 弹出编辑框：上半是选区预览（保留原格式，公式、加粗、行内代码都在），
  下半是**可选**评论框。点勾确认后，这条注释才进入下方输入框。
  同时在答案右侧留一个彩色小圆标。
- **在侧边聊天中提问** —— 在右侧栏新开一个标签页，就这段引文单独对话，
  不创建会话、不写会话事件，主对话不受影响。

## 注释是内联的

注释进入输入框的形式是**真正嵌入正文的原子芯片**，不是单独一块文本：

```
请对比这两处[① 内容 1]和这里[② 内容 2]，然后给结论
```

芯片来自宿主编辑器自己的 `reference-chip` 节点（`@文件` 那种）。它跟文本同处一个段落，
中间可以任意打字、换行、删除：

- 方向键一步跨过芯片，Backspace 整块删掉；
- 芯片前后都是你自己的话，位置完全自由；
- 悬停芯片，上方浮出卡片：评论 + 渲染后的正文 + 右上角 ×，点击卡片跳回原文。

### 芯片的样子由宿主自己画

宿主有一个 `ReferenceChip({ label, appearance, invalid })` 组件，它渲染的是
「标记字形 + label」——也就是说**芯片的外观和文字本来就归宿主管**。
插件只做两件 CSS 的事：隐藏那个 `@` 字形（`> span:first-child{display:none}`），
以及用 `::before { content: attr(data-qc-num) }` 画一个编号徽章。

这一条走了很远才想明白。之前几版都在**用浮层去盖住芯片**，于是宿主的「内容 1」
和浮层的「内容 1」叠在一起，变成截图里那种双影 —— 我以为是样式没调好，
实际上是根本不该重画。

## 为什么不往芯片里塞节点

芯片是 Lexical 的 `ReferenceChipNode`，它自己的注释写着：

> Mount the chip's host element; **the decorator portal renders into it**.

那个 `<span>` 是 React 的渲染目标。往里 `append` 或改 `textContent`，会让 React 的树
和真实 DOM 不一致 —— **输入框当场不能打字**。这条踩过一次，现在代码里只写
`dataset` 属性，并由 `test/chip-dom-guard.mjs` 静态守住。

## 卡片只在悬停时出现

卡片是覆盖在芯片上方的浮层，不是芯片的子节点（子节点会被 React 抹掉）。
常显的话它必须时刻跟随芯片的盒子，而测量与绘制之间只要有滚动或字体加载就会错位；
只在悬停时出现，它在屏幕上的时间很短，错位无从发生。

卡片里**不再重复「内容 N」**——芯片上已经有了，重复一遍就是双影的来源。

## 内容不进草稿，进 codec

芯片在草稿里**只有一个占位符**，正文和评论都不在草稿文本里。

这不是取巧，而是框架的既有设计。插件注册一个引用源（`inputTriggers.registerSource`），
框架在两个时刻回调它：

| 时刻 | 回调 | 用途 |
|---|---|---|
| 发送 | `codec.serialize(ref)` | 把芯片展开成模型该看到的文本 |
| 点击芯片 | `openReference(session, ref)` | 跳回原文 |

所以草稿里是干净的 token（可移动、可整块删除），发送时展开成：

```
[内容 1]
这里要展开（用户的评论）
累计优惠的计算方式如下……
```

块前后各有一个换行，因为芯片可能落在句子中间——拼接时正文会直接粘上展开内容
（`……如下和这里`），模型就分不清哪句是用户的话、哪段是引文。

**最初没注册这个源，就是两个 bug 的共同根因**：芯片是个没有 owner 的惰性 token，
点击没人响应，内容只能当作普通文本塞在芯片外面。

## 为什么卡片不在输入框之外单独隔离

输入框是 Lexical 编辑器，节点类型创建时固定，插件不能新增自定义节点类型。
但 `references` 通道允许复用官方的芯片节点——这就是内联卡片能成立的原因。

**卡片的视觉就长在芯片上，没有任何坐标计算。** 之前几版都是画一个 `position: fixed`
的浮层去覆盖芯片测出来的矩形；那等于把浏览器已经排好版的东西又手工摆一遍，
两套位置只要有一点不同步就错位（换行、测量与绘制之间滚动、字体晚加载）。
改为直接给芯片的 DOM 节点加样式、并把悬停面板挂成它的子节点——
位置完全交给编辑器的排版，插件不再猜任何坐标。

## 荧光高亮

跳转高亮用浏览器的 `CSS.highlights` 注册一个 Range，而不是画 fixed 的 div：

```js
CSS.highlights.set('quote-chat-flash', new Highlight(range))
```

关键在于 **Range 是活的**：滚动、重排、窗口缩放时浏览器会把高亮重新投影到文字上。
之前用 `getClientRects()` 量一次再画盒子，等于给位置拍了一张照片，页面一动照片就过期了——
你截图里荧光糊在输入框上、而原文早已滚出屏幕，就是过期照片的样子。

## 表格

鼠标移过答案里的表格，右上角出现「添加到对话」。表格**独占一张芯片**，
不会被文本选区一并囊括；发送时是 Markdown 表格。
数学公式与符号属于文本，随文本一起进同一张卡片。

## 已修的问题

- **选区只识别前几个字**：`selectionchange` 在指针仍按下时就触发，浮层提前出现并吞掉了
  剩余手势，选区被冻结在起点附近。现在 `pointerdown/pointerup` 门控所有求值，
  键盘路径只在 `keyup` 后取选区。
- **卡片被隔离在输入框外**：原来把整块 `【内容 N】` 文本追加到草稿尾部。现在改为内联芯片，
  内容交给 codec。
- **点击无法回到原文**：这条之前我判断错了三次，真正的根因是**聊天记录会分页卸载**。
  滚远之后，消息行会从 DOM 里被移除（虚拟化），等滚回来再重建。锚点查不到不是"引文没了"，
  而是"那一行还没被加载回来"。
  现在跳转会**主动滚动翻页**：先向上扫到底，再回到原位向下扫，每步等两帧给虚拟化器
  挂载的机会，直到引文出现或对话不再移动。向上的扫描优先，因为旧注释多半在上方。
  连带修掉的三处：
  1. 路径曾**相对所在行**抓取，跨段落选区的 `endPath` 不是起始行后代 → `null` → 整条路径分支被跳过。
     现在相对整个 flow 抓取。
  2. 只在起始行里搜索兜底。现在按 路径 → 行内文字 → 整个 flow 三级回退。
  3. 重建出的范围只校验"非空"，可能指向无关句子。现在必须与引文空白折叠后一致。
- **高亮不跟随文本**：荧光曾经只糊住屏幕一块、而原文已经滚走。根因是拿
  `getClientRects()` 量一次坐标再画 fixed 盒子——那是位置的一张快照。
  现在改用 `CSS.highlights` 注册 Range，浏览器自己把高亮绑在文字上。
- **`no chat flow`**：flow 槽锚点是 `display: contents`（框架自己的注释写着
  "keeps the wrapper out of layout"），这种元素**没有盒子**，`getClientRects()` 恒为空，
  而存活判断恰好用它——于是每一个有效 flow 都被自己跳过。改为看子元素是否占位。
- **卡片错乱/压住文字**：卡片曾是固定定位浮层，边框和内边距都比芯片大，还带 52px 最小宽度，
  横向溢到相邻的字、换行时又盖住上一行。现在视觉直接长在芯片节点上，面板是芯片的子元素。
- **添加后多出空行**：`withAppendedChip` 曾硬编码 `\n\n`。现在按需插入单个换行。
- **删除芯片后偏移错位**：`withoutChip` 曾只切到行尾，留下悬空换行把后续芯片 offset 全推偏一位。
  现在按"芯片是否独占一行"决定吞掉哪个换行。

## 侧边聊天

上：引文。中：问答记录，助手回答下带「加入当前对话」。下：输入框（Enter 发送、Shift+Enter 换行）、停止。

答案来自本插件的 Host 半：

```
POST /quote-chat/api/ask
{ "quote": "…", "question": "…", "history": [{ "question": "…", "answer": "…" }], "locale": "zh" }

→ text/event-stream
  {"type":"delta","text":"…"} …   {"type":"done"}   或   {"type":"error","message":"…"}
```

- 模型路由取配置里的**默认模型**（`ctx.agentDefaultModel`），即新对话会用的那条。
- 历史折进**一条** user 消息，不伪造消息链。
- 引文放进 system prompt 的 `<quote>` 段，模型只知道这段引文。
- 关标签页或点停止即中断上游流。

## 落点

| 部分 | 位置 |
|---|---|
| 芯片 | 输入框草稿内部（`setDraft` 的 `references` 通道） |
| 卡片 / 浮层 / 小标 / 荧光 | `conversation.input.dock` 的一个条目 + `createPortal` 到 `document.body` |
| 侧边聊天 | `ctx.sidebarRightTabs.register()` + `sidebar.right.pane.tab`，用 `sidebarRight.openTab()` 打开 |

只读两个宿主标记：`[data-slot="conversation.chat.flow"]` 与 `[data-chat-node-key]`，
用于判断是否在回答区、以及为小标与跳转定位具体回答行。

## 配置与依赖

无需配置。运行期依赖：`slots`、`locale`（浏览器半），`webServer`、`connection`、`llm`、
`agentDefaultModel`（Host 半）。右侧栏不存在时只保留注释功能。

## 已知边界

- 注释元数据只在**当前页面生命周期内**保存；芯片本身随草稿持久化。
  刷新后芯片还在（草稿存了 references），但卡片外观与右侧小标不再绘制。
- 划词只在主对话回答区生效；右栏标签页内的选择会被忽略。
- 芯片只能追加到草稿末尾；落点之后可用键盘随意移动文本。
- 表格与公式以 Markdown / 原文进入草稿，不保留富文本样式（卡片预览是渲染过的）。
